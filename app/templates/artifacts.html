Test builds from workflow artifacts

Staging one is like uploading its zip: it must hold exactly one APK, up to {{ max_mb }} MB, whose signature verifies. Debug builds are allowed and marked. Only builds from this repo's own branches are listed: never one from a pull request opened from a fork, and never a release's own build (that's under Releases). Builds of the same commit are grouped.

Which build to pick
  • signed · same key as releases is the one to install: a phone that has the app from this repo's releases takes it as an update, keeping the app's data, and the next release updates it again.
  • signed · different key is properly signed, but not by the key the releases use: a phone with the release installed refuses it until the app is uninstalled (which deletes its data).
  • debug build is signed with a throwaway debug key made on the build machine. It identifies nobody, and a phone with the signed app refuses it as an update. Fine on a test phone that never had the release.
  • unsigned can't be installed at all, unless you let this server sign it (Unsigned builds, below).

How a build is signed is only known once it's downloaded: Check signing downloads it, checks it and deletes it; staging one records it too.
