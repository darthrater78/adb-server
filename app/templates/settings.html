Notifications

ADB Server sends notifications through Apprise, which reaches ntfy, Gotify, Home Assistant, Discord, Telegram, Slack, email, plain webhooks and over 100 other services. Each service is one URL. Tokens and passwords in a URL are masked everywhere they're shown.

Add an Apprise server

If you run an Apprise API server, point ADB Server at it and manage the actual services there. Paste its notify URL — e.g. http://apprise.local:8000/notify/my-key — or the address and config key separately. Tags, if you use them, pick which of that config's services receive these notifications.

Apprise URL guide

Paste the URL for your service. A few common ones:

ServiceURL format
Apprise API serverhttp://your-server:port/notify/your-key
apprise://your-server:port/your-key?tags=phone
ntfyntfy://ntfy.sh/your-topic
ntfys://user:pass@your-server/topic
Gotifygotifys://your-server/AppToken
Home Assistanthassios://your-ha:8123/LongLivedAccessToken
Discorddiscord://WebhookID/WebhookToken
Telegramtgram://BotToken/ChatID
Slackslack://TokenA/TokenB/TokenC/#channel
Pushoverpover://UserKey@AppToken
Emailmailtos://user:app-password@gmail.com
Webhook (JSON POST)jsons://your-server/path
  • Every other service and all options are in the Apprise wiki. An "s" on the end of a scheme (ntfys, gotifys, jsons) means HTTPS — prefer it.
  • Services added here are stored in the app's database on the data volume, unencrypted, like the rest of its state. Services in APPRISE_URLS in .env are shown too, but can only be changed there.
  • This server makes the request, so a URL can point at anything this server can reach, including your LAN.
  • A failed notification never stops a poll or a push; it's logged and skipped.
